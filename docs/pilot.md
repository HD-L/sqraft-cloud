# 试点计划

用一个真实团队验证 PRD 的三个目标，通过后再推广。验收门槛：**试点团队不再互传 .sqraft 文件**。

## 1. 范围

| 项 | 建议 |
|---|---|
| 团队 | 1 个产品团队：1–2 名设计师、3–5 名前端 / 客户端开发 |
| 时长 | 4 周（第 1 周部署与培训，第 2–4 周日常使用） |
| 项目 | 1 个正在迭代的真实项目，至少 1 份 100 MB 以上的设计稿 |
| 环境 | 生产配置（HTTPS、每日备份），不用内网 HTTP 模式 |

## 2. 准备清单（第 1 周）

- [ ] 按 [部署手册](deploy.md) 部署，完成安全检查清单
- [ ] 建账号、建项目、分配角色（设计师 = 编辑者，开发 = 查看者）
- [ ] 设计师安装 Mac 上传客户端，完成一次「浏览器登录 → 上传 → 在网页打开」
- [ ] 开发每人创建 MCP 令牌，接入自己常用的 AI 助手，完成一次「列出页面 → 读布局 → 下载切图」
- [ ] 演练一次备份恢复（在另一台机器上恢复，确认能打开设计稿）
- [ ] 建一个反馈渠道（群或表单），约定每周收集一次

## 3. 衡量指标

数据来自网页「系统」页与审计日志（可导出 CSV）。

| PRD 目标 | 指标 | 达标 |
|---|---|---|
| 设计稿交付不再传文件 | 试点期间设计稿交付方式：私有云 vs 文件 | 第 3 周起 100% 走私有云 |
| 开发 5 分钟内让 AI 读到稿 | 新成员从拿到地址到第一次 MCP 调用成功的时间 | 中位数 ≤ 5 分钟 |
| 一键部署 | 从空机器到可用的部署时间 | ≤ 10 分钟（不含证书等待） |
| 开发真正在用 | 近 7 天 MCP 调用人数 / 开发人数 | ≥ 80% |
| 版本以云端为准 | 设计稿更新次数（上传版本数）、回滚次数 | 每周有更新；回滚有记录可查 |

## 4. 每周检查

- 「系统」页：近 7 天上传数、MCP 调用量与调用人数、存储占用
- 「审计日志」：失败的上传（原因）、被拒绝的 MCP 调用、异常登录
- 反馈：哪些页面 AI 读得不准、缺什么工具、客户端哪里不顺手

## 5. 已知限制（试点前告知团队）

- 网页画布不能点选节点看属性、不能测距；需要精确数值时让 AI 用 `inspect_layout` 读
- MCP 没有「对比两个版本」与服务端截图
- 上传客户端只有 Apple Silicon 版，未签名（首次打开需手动放行）
- 只支持本地账号，暂不支持企业微信 / 飞书 / LDAP 单点登录

## 6. 结束评估（第 4 周末）

1. 汇总指标表，判断是否达标；
2. 整理反馈，按「阻碍使用 / 影响效率 / 锦上添花」分级，排进下一版本；
3. 决定推广范围与时间，评估是否需要单点登录、多实例等 P2 能力。
